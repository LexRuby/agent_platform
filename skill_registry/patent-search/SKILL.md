# 专利检索技能

## 何时使用

用户需要围绕技术方案做专利/期刊调研时使用本技能：

- 自然语言描述技术方案 → 找相关专利（`search_patents`）
- 按 TRIZ 原理（发明原理）拓展检索 → 找跨领域启发专利（`search_by_principle`）
- 找学术期刊论文（`search_journals`）
- 拿到专利 ID 后看完整著录项/摘要/权利要求（`get_patent_details`）

## 何时不使用

- 用户要写交底书/提取技术方案 → 属于「智能写作」技能
- 用户要识别术语本体（fpc/fop）→ 属于「智能写作」技能的 `detect_word_ontology`

## 工具清单（MCP：patent-search）

| 工具 | 用途 |
| ---- | ---- |
| `search_patents` | 自然语言专利检索（基础 + 高级合并，用参数区分） |
| `search_by_principle` | TRIZ 原理拓展检索：给出原理名/编号找启发专利 |
| `search_journals` | 期刊论文检索 |
| `get_patent_details` | 按专利 ID 批量取详情 |

## 典型流程

1. **理解需求**：用户给出技术方案描述。先用一句话复述确认检索意图。
2. **首次检索**：`search_patents`（query=方案描述）。返回含 total 与专利列表（ID、标题、相似度）。
3. **收敛**：
   - 结果太泛 → 让用户补充限定词（应用领域、结构特征）后重检；
   - 需要跨领域启发 → 追加 `search_by_principle`（原理名从方案推导，如"分割""嵌套"）；
   - 需要学术背景 → `search_journals`。
4. **详情**：挑出高相关专利（相似度排序前 10 以内），`get_patent_details` 取详情，向用户摘要技术要点。
5. **移交**：用户确认专利集合后，转入「智能写作」技能做方案抽取与筛选。

## 注意事项

- 结果以 ID 引用中间状态：详情查看前不要把全部命中 patent 全量拉详情，先让用户/上下文收敛。
- 一次检索返回过多时优先建议加限定，而不是翻页到底。
- 相似度是排序依据，不代表法律相关性；涉及侵权/规避判断必须提示用户人工确认。
